# 学习笔记：多 Agent 会撞上什么问题？

本目录是仓库的**理论入口**。代码（`src/macs/`）是对照实验，不是学习目标本身。

## 怎么读

推荐顺序：

1. 先读本页，明确学习目标
2. 按编号读问题文章（每篇：问题 → 常见方案 → 我们怎么做 → 代码在哪 → 还缺什么）
3. 再跑一次 `macs`，对照 `runs/<id>/` 里的产物验证直觉
4. 需要产品细节时，再看 [`.scratch/multi-agent-coding-assistant/`](../.scratch/multi-agent-coding-assistant/)

原则：

> **问题驱动，而不是功能驱动。**  
> 先问「多 Agent 会遇到什么」，再问「这段代码实现了什么」。

## 一句话地图

```text
用户目标
  → 固定角色分工（组织图）
  → 本次任务规划（工作图）
  → 显式执行顺序与分支（执行图）
  → 用结构化产物协作（不是群聊）
  → 硬冲突程序检出 + LLM 提案 + 人闸裁决
  → 写码进隔离 worktree
  → 检查失败按所有权打回
  → 交付 PR 草稿，主线仍由人控制
```

## 诚实边界

本仓库**已经演示**的问题：角色分离、产物通信、人闸暂停/恢复、硬冲突检测、写隔离、失败路由、可测接缝。

**意识到但实现仍弱**的问题：软语义冲突、真并行扇出、读懂已有大仓库、多轮修到测试全绿、多分支自动合并。

学习时把「演示了」和「只是提到了」分开，避免把参考实现误当成完备方案。
