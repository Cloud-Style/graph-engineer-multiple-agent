# 02 — 通信：Agent 之间如何传递信息

## 1. 什么是通信？

通信是 Agent 在协作过程中，把自己的信息、决策和结果交给其他 Agent（或下一阶段）的过程。

例如：

- Contracts 要把「共享 API 约定」交给各 Module Designer
- Designer 要把模块设计交给 Reconciler
- Reconciler 要把冻结设计交给 Implementer
- Reviewer 要把失败原因交回责任 Implementer

如果没有通信设计，多 Agent 系统要么变成一锅聊天记录，要么每个角色各自为政。

## 2. 有哪些常见方案？

### 方案 A：直接消息（群聊）

Agent A 直接给 Agent B 发自然语言消息。

- 优点：直观，像开会
- 缺点：顺序依赖强、难结构化、难测试、难暂停恢复、容易越聊越长

### 方案 B：中央协调者转发

所有消息先到 Supervisor，再由它转发给 Worker。

- 优点：有中心控制
- 缺点：Supervisor 上下文膨胀；它可能错误摘要；成为单点瓶颈

### 方案 C：共享状态

大家读写同一份内存/状态对象（blackboard）。

- 优点：下游不必知道上游是谁
- 缺点：若不限制字段与写入权，状态会变成乱炖

### 方案 D：正式产物协议

上游写出结构化文件（契约、设计、冲突报告），下游读取文件。

- 优点：可 diff、可审计、可 resume、可用夹具测试
- 缺点：要先设计字段；对「还没结构化」的软分歧不敏感

### 方案 E：事件总线

发布 `design.completed` 之类事件，别人订阅。

- 优点：解耦、适合分布式
- 缺点：本地 CLI 规模通常过重

## 3. 我们用的是什么？

我们用的是：

> **图编排下的「共享执行状态 + 正式产物」**  
> 不是 Agent 之间的自由聊天。

两层要分开看：

### 短期：同一次图执行里的 `PipelineState`

当前 run 进行中，节点通过共享状态拿到：

- `goal`、`phase`
- `contract`、`designs`、`frozen_design`
- `tasks`、`review`、`decision`

它回答：「这一步执行还需要哪些内存里的信息？」

### 长期：`runs/<run-id>/` 里的产物文件

例如：

- `contract.json`
- `designs/*.json`
- `conflicts.json`
- `frozen_design.json`
- `implementations.json`
- `pipeline_state.json`

它回答：「暂停之后、换进程之后、人或测试打开目录时，真相是什么？」

人闸暂停后进程可以结束；`resume` 靠读回 `pipeline_state.json`，而不是靠某个 Agent 还活着。

### 明确不是「Agent 间通信」的东西

| 东西 | 它是什么 | 它不是什么 |
|---|---|---|
| 调用 LLM（`LlmPort.complete`） | 节点完成自己任务的算力 | Agent A 给 Agent B 发消息 |
| `events.jsonl` | 审计日志（发生过什么） | 业务协作主通道 |

## 4. 为什么这样选？

因为本仓库的学习目标是「可治理的多 Agent」，不是「更像真人开会」。

产物协议带来三个直接好处：

1. **可恢复**：中断后能继续
2. **可审计**：能打开 JSON 看决策痕迹
3. **可测试**：测试断言文件与 `RunResult`，不必断言 prompt 文笔

代价也很清楚：字段设计不好，冲突就检不出来（你已经在真实场景里见过「软冲突检不出」）。

## 5. 代码 / 实验在哪

- 状态与节点流转：`src/macs/pipeline.py`
- 落盘辅助与 run 目录：`run()` 创建 `runs/<id>/`，各节点 `_write_json(...)`
- 审计事件：`src/macs/events.py`
- 接缝恢复：`src/macs/run.py` 的 `resume`

建议实验：

```bash
macs run "ship [modules: app]" --repo /tmp/macs-comm --auto
ls /tmp/macs-comm/runs/*/ 
cat /tmp/macs-comm/runs/*/events.jsonl | head
```

先看产物文件列表，再看 `events.jsonl`：前者是协作内容，后者是审计时间线。

## 6. 还缺什么

- 没有真正的消息队列或跨进程 Agent mailbox
- Designer 目前是循环串行调用，不是多方同时对话
- 产物字段仍偏「硬结构」；语义层通信（例如「这两个字段其实是一个意思」）基本没有
